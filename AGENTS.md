# AGENTS.md — KarmaLab Tools

A small multi-page web app: a collection of browser-based tools, each on its own
route, built with **React + Vite** and served by a small Node server that also
proxies the Replicate API. Built for KarmaLab (Pierre's production company). The
flagship tool is the Batch Image Studio (generates one image per text prompt via
Replicate, in batch); the Continuous Video Studio chains video clips (each clip
starts from the last frame of the previous one, extracted in-browser via
canvas); the Video Effects tool applies real-time WebGL2 effects to an uploaded
video entirely in the browser (no Replicate); the Prompt Box is a styled mockup.

## Routing: on the backend (multi-page)

Each tool is a **separate Vite HTML entry** with its own JS bundle. There is no
client-side router — the tools are independent (no shared shell or cross-tool
state), so a multi-page setup keeps each bundle small (the heavy Batch Studio JS
never loads on the Prompt Box) and lets the Node server own routing. `dist/` is
generated by `vite build`; the server maps clean routes to the built HTML.

## Layout

- `index.html` / `video-chain.html` / `video-effects.html` / `prompt.html` —
  Vite HTML entries (routes `/`, `/video-chain`, `/video-effects` and
  `/prompt`), each loading a script from `src/entries/`.
- `src/entries/` — mounts each tool's root React component.
- `src/apps/` — the tools: `BatchImageStudio.jsx`, `ContinuousVideoStudio.jsx`,
  `VideoEffects.jsx`, `PromptBox.jsx` (styled with Tailwind utilities — no
  co-located CSS). Batch Studio logic lives in `src/apps/batch/` (`models.js`,
  `replicate.js`, `storage.js`); Video Studio logic in `src/apps/video/`
  (`models.js`, `frames.js` — end-frame extraction via off-screen `<video>` +
  canvas); Video Effects logic in `src/apps/effects/` (`gl.js` — WebGL2
  helpers, `engine.js` — the render engine reading frames from the shared
  `<video>` element; effects COMBINE: the engine runs a chain where each
  enabled effect's output texture feeds the next one's `u_tex`, with stateful
  resources — history atlas, feedback, sim, particles — allocated per effect
  id, `effects.js` — the 20 effect definitions: UI metadata + GLSL ES 3.00
  fragment shaders). Effect-card preview thumbnails go in
  `public/effect-previews/<effect-id>.jpg` (gradient placeholder until then).
  Unlike the other tools, Video Effects uses the full window width and needs
  no API key — everything runs client-side in WebGL2.
- `src/shared/videoExport/` — reusable in-browser video export pipeline
  (decode → optional per-frame render callback → encode → MP4), used by Video
  Effects and available to any tool: `exportVideo.js` (the orchestrator —
  see its header for the contract), `mp4FrameSource.js` (mp4box.js demux +
  WebCodecs VideoDecoder, faster than realtime, AAC passthrough),
  `seekFrameSource.js` (fallback for non-MP4 sources via `<video>` seeking),
  `mp4Sink.js` (VideoEncoder + mp4-muxer; H.264 → VP9 → AV1). Callers should
  lazy-`import()` it (it pulls in mp4box) and fall back to realtime
  MediaRecorder capture when WebCodecs is missing.
- `src/shared/` — the shared library used by the tools: `theme.css` (the
  Tailwind entry: `@theme` design tokens + base styles + keyframes),
  `components/` (`Spinner`, `IconButton`, `Input`, `Button`, `Panel`, `Brand` —
  links to karmalab.tech, `ImageDrop`, `TopBar` — cross-tool nav + the API key
  button, `ApiKeyModal`, styled with Tailwind utilities — import from
  `src/shared/components`), `replicate.js` (generic prediction create / poll /
  output helpers), `apiKey.js` (the shared API keys in localStorage — the
  Replicate token plus the OpenAI key that only OpenAI models need — edited
  via `ApiKeyModal`), `fields.js` (shared field/control utility-class
  strings) and `useUnloadGuard.js` (beforeunload confirm while a run is in
  progress).
- `server/index.js` — Node server (core modules only): serves `dist/` and
  proxies `/v1/...` to Replicate.
- `server/routes.js` — the route table (clean route → built HTML file).
- `vite.config.js` — multi-page inputs + the dev `/v1` proxy.
- `Dockerfile`, `fly.toml`, `.dockerignore` — fly.io deployment.

## Key constraint: the Replicate proxy

`api.replicate.com` sends no CORS headers, so a browser `fetch()` straight to it
is always blocked. Both the Vite dev server (dev) and the Node server (prod)
forward `/v1/...` to Replicate, keeping the calls same-origin. So: always fetch
relative `/v1/...`, never `api.replicate.com` directly. The Replicate token is
passed through from the browser, not stored server-side.

If this is ever deployed for real, replace the proxy with a serverless function
that holds the token server-side instead of taking it from the browser.

## Running it locally

Package manager is **yarn**; needs Node ≥ 18.11.

```bash
yarn dev          # Vite dev server (HMR) + /v1 proxy — the normal workflow
yarn build        # build both tools to dist/
yarn start        # run the Node server on dist/ (prod-like: build first)
```

`yarn dev` serves `/`, `/video-chain` and `/prompt` on Vite's port (5173). Add a Replicate
token via the top bar's "API key" button (remembered in `localStorage`, shared
by all tools).

## Styling: Tailwind

Styling is **Tailwind v4** (via `@tailwindcss/vite`), CSS-first: the design
tokens live in `@theme` in `src/shared/theme.css` (the single Tailwind entry,
imported once through the shared components barrel), so tokens double as
utilities (`bg-panel`, `text-text-dim`, `border-panel-border`, `font-mono`,
`animate-klb-spin`). Both tools and every shared component are on utilities —
there are no co-located `.css` files. Longer, repeated class strings are pulled
out into local `const` (e.g. `CONTROL`, `FIELD` in `BatchImageStudio.jsx`) or a
variant map (e.g. `IconButton`, `Button`).
